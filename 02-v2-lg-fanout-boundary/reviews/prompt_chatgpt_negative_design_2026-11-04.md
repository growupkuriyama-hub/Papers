## 0. 問いと、反例に要るもの

**問い（原稿 `main.tex` の `op:fanout-two`）。**
- 設定：Σ = {a, b, c}、内容型付け c（語をその文字の集合へ写す）、ファンアウト2、ランク r_max ≥ 2。
- 問い：L ∈ C_{2,c} の reduced good な表示 G に対して、特徴標本の長さは ‖G‖ と θ̄_G の多項式で抑えられるか。
- C_{2,c} の定義は `def:class-cmcf` である。arity 1 と 2 の両方で、内容が成分ごとに等しく、共通の許容文脈を一つでも持つ二つの組は、分布が等しい。二穴の文脈は中央が空でないもの。

**否定の答えに十分なもの**（原稿 `prop:rare-type`、`cor:distribution-representatives`）は、次を満たす族 (L_n, G_n) である。
- L_n ∈ C_{2,c}
- G_n は reduced good で、ファンアウト ≤ 2
- ‖G_n‖·θ̄_{G_n} = n^{O(1)}
- ある型 m について、その型の最短の語の長さ μ_m(L_n) が n^{ω(1)}

さらに一般には、型付き非終端の代表の長さ τ が超多項式でもよい。ただしデータの下界に結びつけるには、`prop:rare-type` か `lem:distinguishing` を通す必要がある。どちらを使うかを明記すること。

否定の答えが得られれば、ファンアウト2でも擬多様体の境界は LG のままになる。これは論文の看板を強くする結果である。

## 1. これまでに分かった必要条件（使う前に、引用元で確かめること）

以下は Claude の要約である。番号は README の Change log の番号。**要約を鵜呑みにせず、必ず元の報告で主張と仮定を確かめること。**

**全体について**
1. 全ての成分が {a,b,c} の型付き非終端では、τ は線形である（原稿 `prop:full-content-types`、(147)）。反例の長い型には、文字の欠けた成分が要る。
2. 可換群の篩いは短い語で検出される（`prop:abelian-filter-short`）。型の集合による部分標的は、一つの型の削除と同じである。
3. 唯一の語の経路では、長い唯一の語には同じくらい長い「他の型の語」が要る（`lem:unique-word-gap`）。二文字の冪等型の唯一の語は5つの形に限られる（`prop:unique-two-letter-shapes`）。

**純粋な a 語（型 {a}）について**
4. 場合 I（b⁴ も c⁴ も、受理語の因子として現れる）では、μ_a は多項式である（定理 I、(126)(128)）。反例は場合 II（どちらも現れない）か場合 III（一方だけ現れる）にある。
5. 場合 II の分岐 (B)（関係のある塊の任意の鎖が SB を持つ場合）では、μ_a は多項式である（定理 II-B、(142)）。場合 III の分岐 (B) も同じ見込みで、(144)(145) で確認中。
   - したがって、純粋な a 語で反例を作るなら、**分岐 (S)** が要る。関係のあるラベルが両側型で、殻 (A_X, B_X) が入れ子 A^m P B^m をなし、二塊の語がない構造である。
   - 殻の片側の端の連は s + t ≤ 3 を満たす必要がある（(142) §7）。
6. 核の種類が有界なら多項式である（(122) 定理B）。反例には Ω(n / log n) 個の相異なる核が要る。
7. 両文字型ラベルの入れ子の段数が有界なら多項式である（(119)）。
8. 重い非終端で、長さ θ̄ 以下の生成組が全て b と c の両方を含むものが要る（(110) 補題M）。
9. 言語全体が一つの加法的な重みの水準に入るなら μ_a ≤ (r+1)²θ̄³（(100)）。指数的な重みを文字に持たせる設計は使えない。

**文字の欠けた型の τ について**
10. 場合 I の τ_X は、同じ (B, π) の侵入節点の反鎖の幅 h に帰着する（(138)(143)）。反例には h が超多項式であることが要る。
11. 一段の SUB は、語全体に現れる文字の集合を変えない（(143) 補題2.1）。
12. 同じ (B, π) の侵入節点は、全て同じ生成 y にそろえられる見込みで、(146) で確認中。

**既に壊れた候補**（再利用しないこと。壊れた理由を確かめ、新しい候補が同じ理由で壊れないかを先に点検すること）
- 括弧付き倍増族・三文字の倍増族 K_n（原稿 `thm:doubling-no-lift`、`prop:three-letter-family`）
- Thue–Morse 型、単一の Parikh 繊維、並べ替えに閉じた繊維（`chatgpt_sl_fanout2_2026-11-01.md`、`chatgpt_parikh_closed_family_2026-11-01.md`）

- 接頭符号 b c^i b と重み付き符号（`chatgpt_weighted_codes_2026-11-02.md`）

## 2. してほしいこと（優先順）

1. **設計仕様を書く。** §1 の必要条件を元の報告で確かめ、反例の族が満たすべき条件を一つの表にまとめる。各行には次を書く。
   - 条件
   - 出典
   - 証明済みか、見込みか
   - 条件同士の緊張関係：例えば「核が多いこと」と「θ̄ が小さいこと」、「分岐 (S)」と「二塊の語がないこと」
2. **標的を一つ選んで候補族を作る。** 次のどちらか、または両方。
   - (a) 型 {a}：場合 II か III の分岐 (S) で、殻の入れ子が超多項式の a を運ぶ族。
   - (b) 文字の欠けた型（例えば開始型 {a,b}、fan-out 1 の成分）：同じ (B, π) の侵入節点が超多項式個並ぶ族。

   いずれも、‖G_n‖·θ̄ が多項式の文法を**明示**すること。
3. **代入可能性を証明する、または壊す。**
   - 所属は証明で示す。arity 1 と 2 の両方を示すこと。
   - 有限の検査（長さ N までの全ての穴の組と許容文脈の列挙）は、**壊れることの証拠**としてだけ使う。壊れたら、その違反を短い証明書として載せる。
4. **壊れた場合は、壊れ方から新しい必要条件を取り出す。**
   - 「この型の設計は全て、この理由で壊れる」という補題の形で書けるか試す。
   - これは肯定の向きにも使えるので、失敗も成果として扱う。
5. **候補が生き残った場合。** 族全体の所属の証明、μ_m または τ の超多項式の下界、‖G_n‖ と θ̄ の多項式の上界を、全て定数付きで書く。
6. どれも完了しない場合は、次の三つを書いて終える。
   - 証明できたこと
   - 止まった場所
   - 次に絞るべき一点

## 3. 計算について

Python 3 の標準ライブラリだけで書き、全文を載せる（Windows の `py -3 script.py` で動く形）。コードを実行できる環境なら実際に動かし、出力をそのまま載せる。実行できない場合は「未実行」と明記し、出力を推測で書かない。

- 文法から有限の切片（長さ N 以下の語）を作る関数、arity 1 と 2 の違反を探す関数を分けて書く。
- 違反の探索では、切片の端の効果に注意する。長さ N で切ると、本当は受理される語が欠けて、偽の違反が出る。違反を報告するときは、関係する4語が全て本当に言語に入る（入らない）ことを文法から確かめる。
- 推論は健全な規則（共通の許容文脈を持つ、成分ごとの内容が同じ組は分布が等しい）だけを使い、各段を種から再生して検査する。
- 有限の検査の結果から、無限の族の代入可能性を推定しない。

## 4. 守ってほしいこと

- 冒頭に、主張ごとの判定の表を置く。検証した主張には「独立に確認」「誤り」「確認できず」のいずれかを、新しい主張には「証明済み／反証／観察／未解決」のいずれかを書く。
- 「自明に成り立つが目的には足りない」主張と、既に知られた補題の特別な場合にすぎない主張は、その旨を表に書く。
- まだ所属を示していない言語に、その所属を前提にした補題を使わない。
- 反例を主張するのは、所属・下界・文法の大きさの全てを証明した場合だけ。証明が一部でも欠けていれば「候補」と書く。
- 下界を書くときは、対象の作用素（B^{≤r}_{2,c}、B_{2,c}、またはクラス全体で特徴標本を持つ集合駆動の作用素）、字母、ファンアウト、ランクを明記する。
- 「最大の特徴標本」と書かない。
- 「境界がファンアウトで動く」とは書かない（この依頼は逆の向きである）。
- 新しい結果が文献で既知かどうか、分かる範囲で書く。分からなければ「未確認」と書く。
