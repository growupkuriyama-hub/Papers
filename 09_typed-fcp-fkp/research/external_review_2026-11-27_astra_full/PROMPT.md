## 出力先と push の規則

出力はすべて次のフォルダに置き、**区切り（下の S1〜S8）が一つ終わるたびに main に push** してください。

`09_typed-fcp-fkp/research/external_review_2026-11-27_astra_full/`

- `STATUS.md`（既にあります）：push のたびに上書き。どこまで終わったか、次にやる区切り、その時点での暫定判定を書きます。
- `findings.csv`（ヘッダーだけ既にあります）：指摘を見つけた区切りで行を追記します。
- `S1.md`〜`S8.md`：区切りごとの報告。一度 push した区切りのファイルは書き換えないでください。
- `checks/`：計算をした場合だけ、そのコードと出力を置きます。

守ること：

1. このフォルダの外のファイルは一切変更しない（原稿、tools、ほかの査読記録も）。
2. main に直接コミットしてよい。force push はしない。push の前に main の最新を取得し、ほかのコミットがあれば rebase してから push する。git が使えない環境なら、GitHub API で main にファイル単位でコミットする（既存ファイルは blob SHA を指定）。
3. コミットメッセージは `09 review (Astra): S<k> done`（途中保存なら `S<k> partial`）。
4. push に失敗したら一度だけ再試行し、だめなら会話に報告して次の区切りへ進む（次の push でまとめて送る）。

## 途中で止まっても使えるように

- あなたは容量の上限で止まることがあります。**区切りを終えたらすぐ push** してください。一つの区切りが長くなりそうなら、半分で `S<k> partial` として push してかまいません。
- 価値の高い区切りから順に並べてあります。どこで止まっても、それまでの push が使えるデータになります。
- 会話で「続けて」と言われたら、`STATUS.md` を読み、次の区切りから再開してください（終わった区切りはやり直さない）。

## 負担を抑えるために

- 各 `S<k>.md` は 150 行程度まで。原稿の文を書き写さず、行番号で指してください。
- 判定は表で：`| 主張 | 行 | 判定 | 根拠（一、二文） |`。判定は **OK**（証明を再構成できた）、**GAP**（結論は正しいが補うべき穴がある。何を補えば閉じるか書く）、**FALSE**（書いてあるとおりには偽。具体的な反例を書く）、**UNCHECKED**（今回は読めなかった）。
- 計算は任意です。する場合は Python 標準ライブラリのみ、$n\le4$ 程度、ネットワーク・ファイル書き込みなし。有限計算は証明の代わりにならないことを明記してください。
- 新しい定理や大きな構成の変更の提案は不要です（気づいたことは各区切りの末尾に 3 行以内で）。
