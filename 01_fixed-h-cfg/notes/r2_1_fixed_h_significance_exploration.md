# R2.1 exploration: why fixed finite-monoid typing is substantive

Status: exploratory note only; **not yet part of the TCS manuscript**.

Purpose: address Reviewer 2.1 without adding a large post-submission theorem.  The three
directions below are checked against Takada's control-set formulation, Coste--Fredouille--
Kermorvant--de la Higuera's typing-bias formulation, and the current fixed-(h) manuscript.

## 1. A precise bridge to Takada control sets

Takada defines a labeled linear grammar, an associate word (the production-label word
of a derivation), and a control set (C\subseteq\Pi^*) over production labels.  His
representation theorem states that a language is linear iff it is generated by a minimal
labeled linear grammar together with a regular control set.

The fixed-(h) framework gives a natural, explicit regular control on **any** labeled
linear grammar.

### Proposition (finite-state control induced by yield typing)

Let
[
  \mathcal G=(N,\Sigma,P,S,\Pi)
]
be a labeled linear grammar, and let (h:\Sigma^*\to M) be a homomorphism into a
finite monoid.  For (F\subseteq M), define
[
 C_{h,F}(\mathcal G)
 :=
 \{\alpha\in\Pi^* :
   S\Rightarrow_{\mathcal G}^{\alpha} w
   \text{ for some }w\in\Sigma^*
   \text{ with }h(w)\in F\}.
]
Then (C_{h,F}(\mathcal G)) is regular.  Moreover,
[
 L_{C_{h,F}(\mathcal G)}(\mathcal G)
 =
 L(\mathcal G)\cap h^{-1}(F).
]

More generally, for each nonterminal (A) and type (mu\in M), the set
[
 C_{A,mu}
 :=
 \{\alpha :
   A\Rightarrow_{\mathcal G}^{\alpha} w,\ h(w)=\mu\}
]
is regular.

### Proof

A linear derivation has at most one nonterminal at every stage.  Write a nonterminal
production as
[
  A\to uBv
]
and a terminating production as
[
  A\to w,
]
where (u,v,w\in\Sigma^*).

Construct a finite automaton over the production-label alphabet with states
[
  N\times M\times M
]
plus one accepting sink.  Its initial state is ((S,1_M,1_M)).  If a label
(pi) denotes (A\to uBv), put
[
 (A,p,q)\xrightarrow{\pi}
 (B,,p h(u),,h(v)q).
]
If (pi) denotes a terminating rule (A\to w), move from ((A,p,q)) to the
accepting state exactly when
[
  p\,h(w)\,q\in F.
]

Indeed, after
[
 S\Rightarrow u_1A_1v_1
 \Rightarrow u_1u_2A_2v_2v_1
 \Rightarrow\cdots
 \Rightarrow u_1\cdots u_k w v_k\cdots v_1,
]
the two monoid registers are
[
 p=h(u_1\cdots u_k),
 \qquad
 q=h(v_k\cdots v_1),
]
so the final test is exactly the (h)-type of the terminal yield.  The automaton is
finite because (N) and (M) are finite.  Hence the control set is regular, and the
displayed equality follows directly from its definition.

### Interpretation

This is the cleanest contact point with Takada:

* Takada uses a regular language over production labels to control a linear derivation.
* Fixed-(h) yield typing induces a particular regular partition of those production
  sequences by terminal-yield type.
* In the linear typed refinement, a symbol (A_mu) can therefore be viewed as
  restricting the derivations from (A) to the regular control set (C_{A,mu}).

This does **not** show equivalence with Takada's learning method and does not show that
arbitrary Takada control sets arise from a terminal monoid typing.  It only gives a
precise finite-state bridge between the two viewpoints.

**Manuscript value:** high.  It directly answers the reviewer's suggestion to investigate
Takada, has a short proof, and uses no new difficult language family.

## 2. Fixed (h) as a finite-state compositional factor feature

A homomorphism (h:\Sigma^*\to M) into a finite monoid is itself a finite-state
device.  Consider the right Cayley automaton
[
 \mathcal A_h=(M,1_M,\delta),
 \qquad
 \delta(m,a)=m h(a).
]
Then
[
 \delta(1_M,w)=h(w).
]
Thus (h(w)) is exactly the finite state reached after reading the factor (w).

This gives a concrete reading of the class parameter:

> fixed (h) is a finite-state, context-independent, compositional feature map on
> terminal factors.

It is stronger than an arbitrary finite feature map because equality of features is a
monoid congruence and is therefore stable under concatenation.

Two basic operations in the manuscript become transparent under this reading.

1. **Refinement.**  If (ker h'\subseteq\ker h), then (h') retains at least as much
   finite-state information as (h).
2. **Product typing.**  (h\times g) is exactly the synchronous product of the two
   finite-state feature devices.  Independent finite features can therefore be combined
   without making the typing target-specific.

### Relation to Coste et al. (2004)

The analogy should be stated carefully.  Coste et al. use externally supplied typing
background knowledge in automata inference.  Their symbol typing
[
 \tau(u,a,v)
]
may depend on the left context, the typed occurrence, and the right context, and they
represent rational typing information by a finite-state type automaton.

Our (h(w)) is **not** the same object and should not be claimed as a special case of
their occurrence typing.  It types a whole terminal factor independently of its
occurrence context and is compositional under concatenation.  The defensible comparison
is therefore methodological:

> both frameworks expose finite-state background information to the learner, but Coste
> et al. constrain occurrence/state typing, whereas fixed (h) constrains which terminal
> factors may be distributionally identified.

**Manuscript value:** medium-to-high as exposition; this is best used as one compact
paragraph, not as a theorem.

## 3. Useful typing as finite congruence separation of distributional conflicts

The current definition has a sharper conceptual reformulation.

For a target language (L), define the **distributional conflict relation** on nonempty
factors by
[
 x\mathrel{\#_L}y
 \quad\Longleftrightarrow\quad
 \mathcal D_L(x)\cap\mathcal D_L(y)\ne\varnothing
 \ \text{and}\
 \mathcal D_L(x)\ne\mathcal D_L(y).
]

Then, directly from the definition,
[
 L\in\mathsf{RS}_h
 \quad\Longleftrightarrow\quad
 x\#_L y\Longrightarrow h(x)\ne h(y)
 \quad
 (x,y\in\Sigma^+).
]

Equivalently, form the conflict graph whose vertices are nonempty factors and whose
edges are the pairs (x\#_L y).  A typing (h) is adequate exactly when no conflict
edge is collapsed by (ker h).  Hence
[
 L\in\mathsf{RS}
]
iff the conflict graph admits a proper finite coloring that is induced by a
finite-index monoid congruence.

This wording explains both positive and negative facts already in the manuscript.

* **Refinement is safe:** a finer congruence cannot newly collapse a conflict edge.
* **Product features combine:** (h\times g) is adequate iff every conflict edge is
  separated by at least one component:
  [
    x\#_L y
    \Longrightarrow
    h(x)\ne h(y)\ \text{or}\ g(x)\ne g(y).
  ]
* **Finite-monoid obstruction:** an infinite pairwise-conflicting family cannot be
  colored by finitely many monoid types, recovering the current obstruction lemma.
* **Selecting (h) is a genuine separate problem:** it is a constrained finite
  congruence-separation problem, not merely the arbitrary choice of a convenient
  parameter.

This is largely a conceptual repackaging of the current definition and obstruction
lemma, not a new mathematical theorem.  Its value is that it answers the reviewer's
question "what conditions must a useful typing satisfy?" in one exact sentence.

**Manuscript value:** high as a short definition/remark; low as a claimed new theorem.

## Recommended low-risk integration

The strongest low-risk R2.1 package would be:

1. add the finite-state-control proposition from Section 1 near the linear section;
2. add one paragraph in the Introduction explaining fixed (h) as a compositional
   finite-state factor feature and distinguishing it from Coste et al.;
3. rewrite the existing "When is a typing useful?" paragraph using the conflict
   relation, without presenting the reformulation as a new contribution.

This package directly addresses all three directions named by Reviewer 2.1 while avoiding
a new large expressiveness theorem or a new learning claim.
